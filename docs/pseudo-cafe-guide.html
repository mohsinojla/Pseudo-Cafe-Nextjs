Platform Overview

What is Pseudo Café?

Pseudo Café is a full-stack, multi-tenant restaurant operations platform that manages the entire dine-in workflow — from a customer sitting down to a payment being received — in real time, across every role in a restaurant.

The problem it solves: Most restaurants still run on paper tickets, verbal communication, and separate billing apps. Pseudo Café replaces all of that with a unified digital system where the waiter, kitchen, and cashier all see the same live data instantly.

📊

Owner Dashboard

Live revenue counter, order count, avg order value, table occupancy, and top-selling items — updated in real time without page refresh.

🍽️

Waiter POS

Full-screen floor view with colour-coded table statuses. Click a table, search the menu, add items with per-item notes, and fire to kitchen in one tap.

👨‍🍳

Kitchen Display (KDS)

Live order board — no paper tickets. Items cycle through Queued → Preparing → Ready with a single tap. Late orders highlighted in red after 15 minutes.

💳

Cashier Billing

Itemised bill view, percentage discount (capped by role), payment method selection (Cash / Card / Other), optional reference number, one-click confirm.

👥

Staff Management

Invite staff by email — credentials delivered via Resend. New staff show as Pending until first login, then flip to Active automatically.

📈

Sales Reports

Date-range reports (Today / 7 days / 30 days) showing total revenue, breakdown by payment method, and top 10 items ranked by revenue.

Roles & Permissions

Who uses what

Every user is assigned a role at invite time. Roles are enforced at three layers: the UI (buttons hidden), the API (permission checked server-side), and the database (Row Level Security).

Owner
Full access. Dashboard, menu management, staff management, all reports, all POS screens. Cannot be deactivated.
Manager
Same as Owner except cannot create another Owner. Can invite staff, apply discounts, view reports.
Cashier
Access to Cashier billing screen only. Can apply discounts up to a configured limit (e.g. 10%). Cannot see reports or staff.
Waiter
Access to Waiter POS only. Can view floor, create orders, add items with notes, fire to kitchen, request bill. Cannot see prices in reports.
Kitchen
Access to Kitchen Display only. Can advance item status (Queued → Preparing → Ready). No access to prices, staff, or reports.

Real-Time Architecture

What updates live

Supabase Realtime (PostgreSQL logical replication → websocket) powers three live views simultaneously:

🟡 Floor View (Waiter)

Table cards update the instant another waiter changes status. Two waiters cannot double-order the same table.

🟠 Kitchen Display

New orders appear instantly — no page refresh, no polling. Age timer updates every 10 seconds.

📊 Owner Dashboard

Revenue counter increments live when cashier processes a payment. Order count, top items, and occupancy all update in real time.

How to Use

Owner / Manager journey

1

Log in at /login

Enter email and password. Owner and Manager are redirected to /outlet/[id] — the management dashboard. Sidebar navigation gives access to Overview, Menu, Staff, and Reports.

2

Build the menu — /outlet/[id]/menu

Click Add Item. Fill name, price, category, and optionally paste an image URL (Unsplash, CDN, etc.). Leave image blank to use the auto-selected category photo. Toggle availability without deleting items for 86'd dishes.

3

Invite staff — /outlet/[id]/staff

Click Invite Staff. Enter full name, email, select a role, and set an initial password (min 8 chars). Staff receive a branded welcome email with their credentials. They appear with a Pending badge until their first login, then automatically become Active.

4

Monitor operations — Dashboard Overview

The overview shows live: today's revenue (increments on each payment), order count, average order value, table occupancy, and top 5 items sold. Use the three POS quick-links to open Waiter / Kitchen / Cashier views directly.

5

Review performance — /outlet/[id]/reports

Switch between Today, Last 7 days, Last 30 days. See total revenue, breakdown by payment method (Cash / Card / Other), and top 10 items ranked by revenue with quantity sold.

How to Use

Waiter journey

1

Open the floor — /waiter/[id]

Colour-coded table grid: ■ Green = Free, ■ Blue = Seated, ■ Amber = Ordered, ■ Red = Bill requested. Updates live without refresh.

2

Tap a table → build order

The right panel opens with the full menu. Use the search bar to find items instantly. Tap + to add, − to remove. Tap the note icon (📝) after adding an item to set special instructions — "no onions", "extra sauce", etc. Notes appear on the KDS.

3

Send to Kitchen

Cart total shown at the bottom. Tap Send to Kitchen — the order fires to the KDS and the table card turns amber. You can add more items later (they join the existing order). If the API fails, an inline error banner shows the reason — no silent failures.

4

Request Bill

When food is served and the guest asks for the bill, tap Request Bill in the table header. The order moves to billed state and appears instantly in the Cashier queue. The table card turns red.

How to Use

Kitchen & Cashier

Kitchen Display (KDS)

1

Live order cards

Each order appears as a card sorted oldest-first. Table label and elapsed time shown top-right. Orders older than 15 minutes get a red border and ⚠ LATE badge.

2

Advance item status

Tap any item to cycle: Queued → Preparing → Ready. Item badge updates immediately. Special notes from the waiter appear in yellow beneath the item name.

3

Auto-complete

When all items in an order are marked Ready, the order automatically transitions to ready state and disappears from the KDS. The waiter sees the table update live.

Cashier Billing

1

Bill queue

Left sidebar lists all billed orders in the outlet. Oldest first. Click any order to load the full itemised bill.

2

Apply discount

Enter a percentage discount (0–100%). The RBAC system caps this silently at the cashier's allowed maximum — any attempt over the limit returns a 403 error shown inline.

3

Confirm payment

Select Cash, Card, or Other. For card/other you can enter an optional reference/TXN ID. Press Confirm Payment. Payment is recorded, order closes, and the table frees instantly across all devices.

What makes it extraordinary

Beyond a basic POS

⚡

Zero-polling real-time

Every screen — KDS, floor view, dashboard — uses Supabase Realtime (WebSocket). No refresh, no polling. Sub-second latency across all connected devices simultaneously.

🔒

Three-layer security

UI hides unauthorised buttons. API runs can() RBAC check server-side. Database enforces Row Level Security — even a rogue API call cannot read another tenant's data.

🏢

Multi-tenant by design

Every table has org_id. A single deployment hosts unlimited restaurant organisations. No data leakage between tenants at the DB level. Scale to SaaS with zero schema changes.

📧

Branded staff onboarding

Welcome emails sent via Resend — dark-themed HTML with credentials card, role badge, and CTA button. Staff show as Pending until first login; auto-activate without any admin action.

🍕

Per-item kitchen notes

Waiters can attach special instructions to individual items ("no onions, extra sauce"). Notes travel from POS → database → KDS in real time, eliminating verbal re-transmission.

🛡️

State machine enforcement

Orders follow a strict state machine enforced at the API layer. An order cannot skip states or be paid before it's billed. Every transition is audited with timestamps.

Deployment

From code to live URL

This guide takes you from a fresh clone to a publicly accessible deployment on Vercel, backed by Supabase cloud — in under 30 minutes.

Phase 1 — External services setup

1

Create a Supabase project

Go to supabase.com → New project. Choose a region close to your users (e.g. ap-south-1 for Pakistan). Set a strong database password and save it. After creation, go to Project Settings → API and copy:

  • Project URL → NEXT_PUBLIC_SUPABASE_URL
  • anon public key → NEXT_PUBLIC_SUPABASE_ANON_KEY
  • service_role secret key → SUPABASE_SERVICE_ROLE_KEY
2

Apply the database schema

In Supabase dashboard → SQL Editor, paste and run the full migration SQL (found in supabase/migrations/ or run via the Supabase MCP tool). This creates all tables, RLS policies, indexes, roles, and permissions in one shot.

3

Seed demo data (optional)

Run npm run seed locally with your .env.local filled in. This creates a demo organisation, outlet, menu categories, 13 menu items with Unsplash images, tables, and an owner account.

4

Create a Resend account

Go to resend.com → Sign up free → API Keys → Create key. Copy the key as RESEND_API_KEY. On the free tier you can send from onboarding@resend.dev without DNS setup. For production, add and verify your own domain under Domains.

Phase 2 — Local development

# 1. Clone and install git clone https://github.com/your-org/pseudo-cafe.git cd pseudo-cafe npm install # 2. Create environment file cp .env.example .env.local # Fill in the values below, then: # 3. Start development server npm run dev # Open http://localhost:3000

Environment variables

NEXT_PUBLIC_SUPABASE_URL Your Supabase project URL — e.g. https://xyzabc.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY Public anon key from Supabase API settings
SUPABASE_SERVICE_ROLE_KEY Secret service_role key — server-only, never exposed to browser
RESEND_API_KEY API key from resend.com — starts with re_
NEXT_PUBLIC_SITE_URL Your public URL — http://localhost:3000 in dev, https://yourapp.vercel.app in prod

Phase 3 — Deploy to Vercel

1

Push to GitHub

Create a new GitHub repository and push your code. Keep .env.local in .gitignore — never commit secrets.

git init && git add . && git commit -m "Initial commit" git remote add origin https://github.com/your-org/pseudo-cafe.git git push -u origin main
2

Import to Vercel

Go to vercel.com/new → Import Git Repository → select your repo. Framework preset is detected automatically as Next.js. Leave build settings as default.

3

Add environment variables

In the Vercel import screen → Environment Variables section, add all five variables from the previous page. Set NEXT_PUBLIC_SITE_URL to your Vercel deployment URL (e.g. https://pseudo-cafe.vercel.app). You can update this after the first deploy.

4

Deploy

Click Deploy. Vercel builds the Next.js app (~90 seconds) and provisions serverless functions for all API routes. You get a live HTTPS URL instantly.

5

Update Supabase redirect URLs

In Supabase Dashboard → Authentication → URL Configuration. Add your Vercel URL to Site URL and Redirect URLs. This is required for auth redirects to work in production.

6

Custom domain (optional)

In Vercel → Project → Settings → Domains. Add your domain (e.g. app.pseudocafe.com). Vercel provides a CNAME record. Add it to your DNS provider. SSL certificate is auto-provisioned. Update NEXT_PUBLIC_SITE_URL and Supabase redirect URLs to the new domain.

Production readiness checklist

  • All 5 environment variables set in Vercel
  • Supabase Site URL updated to production URL
  • Database schema and migrations applied
  • RLS policies enabled on all tables
  • Owner account created (via seed or manually)
  • Resend domain verified (for custom sender)
  • Menu items added with images
  • Tables configured for the outlet
  • TypeScript build passes with 0 errors (npm run build)
  • Supabase Realtime enabled on project
  • Service role key is server-only (not in NEXT_PUBLIC_)
  • .env.local is in .gitignore
  • Test full order flow end-to-end in staging
  • Test staff invite email delivery
  • Verify KDS live updates on second device
  • Set Supabase DB password to 20+ chars

After deployment, the full stack is: Custom domain (DNS) → Vercel Edge Network (CDN + SSL) → Next.js serverless functions (API routes) → Supabase PostgreSQL (database + auth + realtime) → Resend (email). All connections are encrypted in transit. No infrastructure to manage.
